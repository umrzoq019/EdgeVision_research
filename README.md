# EdgeVision — Accuracy vs. Efficiency in Small CNNs

EdgeVision studies how much CIFAR-10 accuracy a convolutional network keeps as its size and CPU inference cost are cut by orders of magnitude.

> **Research question:** how much accuracy can a vision model retain when its size and CPU inference cost are reduced?

**Status (this checkpoint):** baselines (3 seeds), repeated CPU benchmarking, knowledge distillation (3 seeds + a single-seed ablation) and a first INT8 post-training quantization run are complete. Comparison with established lightweight networks, a stronger evaluation protocol and a final Pareto study are still open — see [`docs/NEXT_STEPS.md`](docs/NEXT_STEPS.md).

## Headline results

| Model | Params | Test accuracy (mean ± SD, 3 seeds) | File size | Tensor payload | Median CPU latency* |
|---|---:|---:|---:|---:|---:|
| SmallCNNv2 | 75,946 | **61.83 ± 1.47 %** | 0.298 MB | 298 KiB | 1.28 ms |
| TinyCNNv2 | 4,218 | 40.03 ± 1.53 % | 0.0215 MB | 16.8 KiB | 0.55 ms |
| NanoCNNv2 | 1,250 | 35.20 ± 0.78 % | 0.0097 MB | 5.1 KiB | 0.37 ms |
| NanoCNNv2 + distillation (T=2, α=0.5) | 1,250 | 35.73 ± 1.27 % | 0.0099 MB | 5.1 KiB | same architecture as Nano |

\*Single-thread, one benchmark session. Latency is the weakest measurement in this project: Nano was measured anywhere between 0.32 and 0.53 ms across sessions, so treat the ratios (≈2.3× Tiny, ≈3.4× Nano vs Small) as indicative only. See [Known issues](docs/KNOWN_ISSUES.md).

**What the evidence supports**

1. **A large accuracy/efficiency trade-off exists and is clear.** Nano has 98.4 % fewer parameters than Small and loses 26.6 percentage points (paired difference over seeds, 95 % CI +23.7 … +29.5 pp). Small vs Tiny is also unambiguous (+21.8 pp). Tiny vs Nano (+4.8 pp) is suggestive only (p ≈ 0.07, n = 3).
2. **Knowledge distillation did not measurably help NanoCNNv2.** Paired gain +0.53 pp, 95 % CI −4.6 … +5.6 pp, p ≈ 0.70; per-seed differences were −0.7, +2.9, −0.6 pp, so one seed produces the whole mean gain. This is a result for the tested setup (weak 62 % teacher, 9,000 training images, 30 epochs), not a claim that distillation never works.
3. **The distillation ablation cannot rank its settings.** Three single-seed runs span 34.6–35.8 % test accuracy, within the ≈ ±1.5 pp binomial noise of a 1,000-image test set, and the same nominal configuration gave 35.8 % in the ablation but 35.0 % in the multi-seed run.
4. **INT8 post-training quantization (Nano, seed 42 only):** accuracy 35.7 → 34.1 % (−1.6 pp, within noise), file size −13.4 %, latency ratio 1.06× slower — but FP32 round timings drifted by 60 % inside that run, so the latency result is inconclusive. A 1,250-parameter model is dominated by quantize/dequantize and file-container overhead, so a large INT8 speed-up was never likely.

## Protocol in one paragraph

CIFAR-10, 32×32 RGB. 10,000 training images are drawn with a seeded permutation; 1,000 of them form the validation set (used for checkpoint selection) and 9,000 are used for training with random-crop (pad 4) and horizontal-flip augmentation. Test accuracy uses the **first 1,000 CIFAR-10 test images**. 30 epochs, batch 128, AdamW (lr 1e-3, weight decay 1e-4), cosine schedule, seeds 42 / 123 / 456. CPU latency uses one PyTorch thread. Details: [`docs/V2_METHODOLOGY.md`](docs/V2_METHODOLOGY.md).

## Reproducing

Run everything from the repository root. Reruns should write to new directories so the preserved results are not overwritten.

```bash
pip install -r requirements.txt

# 1. baselines, 3 seeds (≈ 18 min per seed on the CPU runtime used originally)
python src/multi_seed.py --seeds 42 123 456 --output-root results/multi_seed_rerun

# 2. distillation, 3 seeds (T=2, alpha=0.5; ≈ 7 min per seed)
python src/multi_seed_distill.py --seeds 42 123 456 \
    --baseline-root results/multi_seed_rerun --output-root results/distillation/multi_seed_rerun

# 3. ablation (3 settings, ≈ 8 min each)
python src/distill_ablation.py --teacher results/multi_seed_rerun/seed_42/SmallCNNv2.pt \
    --out-dir results/distillation/ablation_rerun

# 4. interleaved latency (recommended instead of benchmark_repeated.py)
python src/benchmark_interleaved.py --checkpoint-root results/multi_seed_rerun --out results/latency/interleaved.json

# 5. INT8 post-training quantization
python src/quantize_ptq.py --checkpoint results/multi_seed_rerun/seed_42/NanoCNNv2.pt --out-dir results/quantization_rerun

# 6. tables, statistics, figures (defaults read the preserved results in results/)
python src/final_analysis.py
#   for reruns:  --baseline-dir results/multi_seed_rerun --distill-dir results/distillation/multi_seed_rerun
```

`notebooks/EdgeVision_v2_runner.ipynb` runs the same sequence in Colab. The original working notebook is here: [Colab](https://colab.research.google.com/drive/1bypBQJrqnrKD0ncEd4RWQjRP_QVjpxne) (not a byte-for-byte copy of the runner; export the original `.ipynb` if you need it verbatim). ## Limitations

- 1,000-image test subset: one accuracy value carries ≈ ±1.5 pp binomial standard error. Only 3 seeds, so confidence intervals are wide.
- Only 9,000 training images: absolute accuracies are far below what these architectures reach on full CIFAR-10, and the teacher is weak, which limits what distillation can add.
- CPU latency depends on hardware, load and measurement design; no CPU model or library versions were recorded for the original runs.
- INT8 evidence is one model, one seed, one timing session.
- The distillation ablation is single-seed and its "best" setting was first identified by test accuracy (validation accuracy ranks the settings differently).
